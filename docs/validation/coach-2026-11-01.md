# Préparation de la validation Coach — 1er novembre 2026

## Vérifications exécutées

Branche de travail `feat/grounded-coach`, worktree isolé. Le corpus Riot du
checkout principal a été utilisé sans réingestion. La commande réelle
`evaluate-coach`, avec `--offline-model` et sans `--live`, a chargé le modèle
d'embedding en cache et préparé les 37 questions de `evaluation/retrieval-v1.json`.

Résultat : `planned`, **zéro appel Gemini**. Le rapport local est
`.runtime/coach-plan-2026-11-01.json` dans le worktree Coach. Il n'est pas
versionné avec les données d'exécution.

La suite hors ligne comporte **86 tests passants**, dont le roundtrip CLI
avec Qdrant en mémoire, le plan sans clé, la limite des tentatives, l'arrêt
au quota, les cas non exécutés et la saisie de clé masquée simulée.
Ruff check et format check passent. Les tests utilisent l'environnement
Python déjà installé, via uv `--no-sync` et `PYTHONPATH` sur le worktree ; aucune
dépendance n'a été ajoutée et aucune synchronisation du lock n'était nécessaire.

## Limites

Lors de la préparation, `GEMINI_API_KEY` était absente de l'environnement
accessible à l'agent. Elle a ensuite été chargée explicitement par uv depuis
le `.env` indiqué par le propriétaire, sans affichage de son contenu. Le fichier
est ignoré par Git et non suivi. Les paramètres de facturation ne sont pas
vérifiés par le code. Le budget nul exige un projet Google sans facturation,
à vérifier par le propriétaire. L'appartenance des références est contrôlée
par code ; leur soutien sémantique doit être relu sur les réponses réelles.

Le plan utilise les annotations du retrieval comme attentes provisoires ; il
ne constitue pas un jeu de référence complet de génération. Les champs de
revue humaine restent à remplir. Ne pas annoncer un taux d'exactitude à partir
de ce plan ou des tests à transport simulé.

Le [guide Coach](../coach.md) fournit les commandes pour lancer le lot réel
avec une clé locale et trois tentatives maximum par défaut.

## Diagnostic d'intégration réelle

Les lots initiaux se sont arrêtés dès la première erreur, sans retry. Le
diagnostic sur `gemini-2.5-flash` a révélé HTTP 404 : modèle fermé aux nouveaux
utilisateurs. La consultation de sa fiche retournait pourtant HTTP 200 ;
cela ne prouve donc pas sa disponibilité pour la génération. La réponse API
recommande `gemini-3.8-flash`, désormais sélectionné par l'adaptateur avec
raisonnement `LOW`. Des diagnostics HTTP expurgés ont été ajoutés au résultat
Coach. Aucun corps d'erreur fournisseur ou secret n'est conservé dans celui-ci.

## Premier lot réel réussi

Rapport local : `.runtime/coach-live-2026-11-01-d.json`. L'appel utilise le
vrai corpus, le véritable encodeur en cache et Gemini `gemini-3.8-flash`.
Le résultat global est **partial** avec un budget d'une tentative :

- Une réponse `answered` sur « Comment fonctionne Orbe d'illusion chez Ahri ? ».
- Treize cas négatifs traités sans génération : quatre hors corpus, sept
  demandes de précision et deux absences de patch/langue.
- Vingt-trois cas positifs non exécutés, conservés dans le rapport.
- Durée mesurée pour la réponse : **69 325,971 ms**, hors chargement et retrieval.

L'agent de développement a relu les deux faits sur les trajets aller/retour
et les types de dégâts : ils correspondent au passage Riot cité. Le conseil
de positionnement est étiqueté comme hypothèse et l'exercice est présent.
Aucune valeur numérique de dégâts n'est ajoutée ; les données manquantes sont
mentionnées. La référence retournée est
`29512b8e-3725-5421-9b40-7a063720d55a`, section `spell:AhriQ`, patch `16.21.1`.

Ce contrôle par l'agent n'est pas une revue pédagogique humaine indépendante.
Les champs `human_review` restent à `null`. Un cas positif réussi ne donne pas
un taux d'exactitude général. La latence est élevée pour une interface
interactive ; elle doit être mesurée sur davantage d'exemples avant le cloud.

Le premier essai 3.8 avait dépassé 45 secondes ; le délai de lecture a été
porté à 90 secondes puis la commande complète a réussi. Aucun retry automatique
n'a été ajouté. Les essais de diagnostic ont été lancés explicitement et
constituent des tentatives distinctes des budgets de chaque rapport.

## Évaluation complète Flash-Lite

Le lot final contient **37 cas exécutés** : 24 réponses et 13 abstentions ou
clarifications attendues. Les 37 statuts correspondent aux annotations et
aucune référence inconnue n'est retournée. Les 24 appels gratuits ont été
espacés de cinq secondes ; aucun quota ou retry n'a été rencontré dans ce lot.
La génération médiane est de **1 676 ms**, le p95 observé de **2 156 ms**,
hors pauses, chargement et retrieval.

Le [rapport versionné](../../evaluation/reports/coach-complete-2026-11-01.json)
contient les réponses, citations et limites, sans textes bruts du corpus.
Le rapport complet avec contexte reste local dans
`.runtime/coach-complete-2026-11-01.json`. Les faits des 24 réponses ont été
relus par l'agent contre les passages. Deux points pédagogiques ont été
relevés : un exercice de Téléportation demandait une durée absente ; Aery
transcrivait des coefficients sans assez expliquer leurs limites. Le prompt
a été précisé et ces deux cas ont été rejoués. L'exercice de Téléportation
demande désormais le type de cible ; Aery explicite l'absence de valeurs exactes,
mais sa transcription de formule reste perfectible.

Ces observations ne sont pas une validation humaine indépendante ni une
garantie de qualité générale. Le lot de 37 cas précède l'ajustement ciblé du
prompt ; seuls les deux cas concernés ont été rejoués après cet ajustement.
Le contrat de génération n'a pas changé. Les tests hors ligne du Coach et de
son évaluation couvrent désormais l'espacement des appels ; ils passent sans clé.
